3. 文本：三语法混写

一段字符串里可以同时写四种语法，走 api.text() 统一解析：

TextService text = api.text();
Component c = text.parse("&c<bold>血量 <sprite:gui:hud/heart/full> <shadow:#20000080>10");
语法 例子
MiniMessage <red> <gradient:#ff0000:#0000ff> <bold>
旧版颜色码 &a &l &r（§ 同理）
旧版十六进制 &#2ecc71
内联贴图 <sprite:gui:hud/heart/full>
文字投影 <shadow:#20000080>

sprite 图集与路径

必须带图集名。 省略图集时默认图集是 minecraft:blocks，而 GUI 贴图在 minecraft:gui 图集里：

✗ <sprite:hud/heart/full>                     查不到
✓ <sprite:gui:hud/heart/full>                 对的

不要写全限定名而不加引号。 MiniMessage 按冒号切参数：

✗ <sprite:minecraft:gui:hud/heart/full>
     → atlas=minecraft:minecraft, sprite=minecraft:gui  ← 不报错，静默出错
✓ <sprite:'minecraft:gui':'minecraft:hud/heart/full'>

sprite key 怎么查：拿客户端 assets 里的贴图路径，去掉 textures/gui/sprites/ 前缀和 .png 后缀。

assets/minecraft/textures/gui/sprites/hud/heart/full.png
  → <sprite:gui:hud/heart/full>

（要自己核对图集的话，从客户端 jar 里导出 assets/minecraft/textures 看。）

三个图集，别记混：

图集 写法 例子
minecraft:blocks 可省略图集名（它是默认值） <sprite:block/anvil>
minecraft:items 必须写 items: <sprite:items:item/diamond>
minecraft:gui 必须写 gui: <sprite:gui:hud/heart/full>

常见缺失路径：

  • item/clock 不存在。 时钟是 64 帧动画，图集里只有 item/clock_00 … item/clock_63。写 item/clock 是紫黑格子。指南针同理（32 帧）。
  • item/anvil 不存在。 铁砧没有独立的物品贴图，它用的是方块模型， 所以要去 blocks 图集拿 block/anvil。

错误路径可能渲染为缺失贴图。建议集中管理 sprite 常量，并与目标客户端资源目录核对。

shadow 颜色

接受 #RGB / #RRGGBB / #RRGGBBAA / 颜色名 / 颜色名:alpha 五种写法。

关掉投影用 <!shadow>，不是 <shadow:none> —— none 不是合法颜色， 标签解析不了会原样当文字显示出来。

版本要求

sprite 要客户端 1.21.9+，shadow 要 1.21.6+。经版本兼容插件进来的低版本 客户端看到的是降级结果，关键信息不要只放在 sprite 里，旁边留一份文字。

4. 文本安全（必读）

parse 的第二个参数是信任级别，这是一条安全边界，不是样式选项。

级别 用在哪 效果
SYSTEM 配置文件、代码常量 全部标签可用，含 click / hover
PLAYER 玩家可控但希望保留配色（队名、房间名） 白名单：只有外观标签
LITERAL 聊天正文、玩家名、外部 API 返回 全部当字面量

不带 trust 参数的重载一律按 SYSTEM 处理。 所以凡是来源含玩家输入的， 必须显式传 PLAYER 或 LITERAL。

⚠ 不要自己 new 一个 NON_INTERACTABLE 的 MiniMessage 就当它安全

实测（Adventure 5.2.0）MiniMessage.Preset.NON_INTERACTABLE 只挡 click / hover / insert，<selector>、<score>、<nbt> 照样生效 —— 其中 <nbt> 能把任意方块 / 实体的 NBT 读进聊天。

本服的 PLAYER 级走的是显式白名单（只放行 color / decoration / gradient / rainbow / transition / pride / reset / newline / font / sprite / shadow）， 将来 Adventure 加了什么新标签也默认是关的。统一走 TextService，不要另起炉灶。

拼接用户输入的正确姿势

用占位符通道，不要手拼字符串：

// ✓ 值走 unparsed，玩家名里的 <click:...> 不会被当标签
text.parse("<gray>队名: <name>", TextTrust.SYSTEM, Map.of("name", userInput));

// ✗ 手拼，等着被注入
text.parse("<gray>队名: " + userInput);

真要手拼就先 text.escape(userInput)。escape 不会丢字符： R&B 还是 R&B，&cRed 会原样显示成 &cRed 而不变红。

实现细节：&& 在本管线里表示一个字面量 &，escape 就是靠它做到「既不生效也不丢字符」。 现有的配置文案里没有 &&，引入这条规则不改变任何既有文案。

5. 风格对齐

所有配色 / 图标 / 音效从 text.style() 取，不要硬编码 &b：

TextStyle s = api.text().style();
s.brand()  s.accent()  s.ok()  s.warn()  s.error()  s.muted()
s.icon("crown")            // 图标，取不到返回 empty 不抛异常
s.color("我的自定义语义色")   // 取不到回落到 body
text.feedback(player, "deny");   // 统一音效

取值全都来自子服的外观配置。改一次配置全服（含所有小游戏） 一起变，换资源包不需要重新编译任何插件。 想加新图标 / 新语义色， 请服主在外观配置里加一行即可。

配置文件里也能用调色板

上面那套只能在 Java 里调。真正让 OP 编的文案也跟着换主题的，是这几个 MiniMessage 标签 —— 走 text.parse() 的任何字符串里都能写：

<brand>标题</brand>  <accent>数值</accent>  <muted>说明</muted>
<ok>成功</ok>  <warn>警告</warn>  <error>失败</error>  <body>正文</body>
<icon:crown>  <icon:heart>  <icon:coin>       ← 外观配置里登记过的都行

它们只能改颜色和插入预先登记过的图标，产生不了副作用，所以两个信任级别都放行 —— 玩家在队名里写 <brand> 最多是让队名变成品牌色。

外观配置缺失或图标段被改坏时，ok / error / warn / info / arrow / back / coin / crown / heart / star / clock / player 这几个图标有内置的纯文本兜底， 不会渲染成空。

已经有自己文本管线的插件

不想整个换掉自己那套解析器（比如你支持 &x&a&1&b&2&c&3 这种本框架不处理的 旧版十六进制），就把调色板挂到你自己的 MiniMessage 上：

MiniMessage mm = MiniMessage.builder()
        .editTags(t -> t.resolver(api.text().styleTags()))
        .build();

不要缓存 styleTags() 的返回值 —— 外观配置热重载后会换一个新的， 缓存住的那个仍然指向旧配色。每次用每次取（可用 Supplier 按需取得）。
