子服准入锁 1.4.6

Happy.api().access() 让大厅上的活动插件锁住目标子服：锁上之后只有放行名单上的人和工作人员能进。抽奖、报名、送人由你的插件自己做，和 活动接管 的 EventApi 无关 —— 不受「同时只有一场活动」和内置抽奖算法的限制，每台子服各锁各的。

依赖方式同其他接口：fakehappy-api 用 provided，plugin.yml 写 depend: [FakeHappy]。代理上要装同版本的 FakeHappy 代理插件。

接口

方法 用途
isAvailable() 跨服层连着才能用
lock(plugin, serverId, options) 锁定；自己已持有时只换选项，名单不变
unlock(plugin, serverId) 解锁，只有持有者能解
setAllowlist(plugin, serverId, uuids) 整体替换放行名单，最多 2000 人
evacuate(plugin, serverId, fallback) 把该服上名单外的人送到 fallback，返回逐人回执；有豁免权限的人不动
evacuate(plugin, serverId, fallback, true) 同上，有豁免权限的人（OP）也送走，只留名单上的人
state(serverId) / locks() 直接读当前状态；插件重启后用来恢复

serverId 是代理配置里的子服名，也认服主配的子服显示名。持有者按插件名区分：别的插件锁着时返回 NOT_OWNER，Result.state() 里能看到是谁。

所有方法返回 CompletableFuture，一般在 IO 线程完成；失败不抛异常，看 Result.status()。state / locks 读不到跨服层时 future 异常完成 —— 读失败和「没锁」要分开处理。

LockOptions(evacuateOnLock, fallbackServer, denyMessage)：

  • evacuateOnLock：锁上的同时清人，future 等清人做完再完成。要逐人结果就再调一次 evacuate。
  • fallbackServer：清人送去哪；直接登录到被锁子服、或锁生效时正在路上的人也送去这里。
  • denyMessage：被拒时玩家看到的文字，null 用「本场活动暂不可进入」。
  • 第四个参数 eventRound 默认 true，见下面「活动期间的奖励与游戏行为」。
  • 第五个参数 exemptMayEnter 默认 true：有豁免权限的人（OP）不在名单上也能进、能上场。传 false 就只认名单：OP 没在名单上也进不去、上不了场，清人时也一起清（三个参数的 evacuate 也清）。例：new LockOptions(false, "主大厅", msg, true, false)。

完整流程见示例 example/src/main/java/maybe_c/happy/example/access/AccessLockExample.java。

行为

  1. 拦在哪：代理切服前拒绝，玩家留在原来的服并看到 denyMessage，不会先进去再被踢。目标服装了 FakeHappy 的话，进服时再查一遍兜底。刚写进放行名单的人紧接着被送过去不会被误拒（代理会再查一次最新状态）。
  2. 豁免权限：AccessService.BYPASS_PERMISSION 或活动的豁免权限，默认 OP 都有。锁的 exemptMayEnter 为 false 时豁免不算数。权限在子服上判断，玩家进任意一台 FakeHappy 子服时同步给代理；直接在代理上给也认。
  3. 持久化：锁存在跨服层，没有过期时间。子服、大厅、代理重启后都还在。
  4. 持有者失效：插件卸载或崩溃时锁保留。重启后用 locks() 找回自己的锁继续管理；管理员可以在 FakeHappy 的管理面板里强制解锁。
  5. 清人范围：evacuate 处理此刻已经在该服上的人（每台代理处理自己手上的，回执汇总）。锁生效时正在连接中的人，到了之后由代理送去锁上记录的 fallbackServer；没设 fallback 时由目标服的 FakeHappy 在登录时拒绝。

有豁免权限的人默认不清（解说、录像、场控要留在服上），回执的 message 会写「另有 N 人有豁免权限，没动」。要连 OP 一起清，用四个参数的 evacuate(..., true)：名单上的 OP 照样留下；清完之后豁免的人自己再连过来不拦。

  1. 强制送人：network().send(玩家们, 子服, true) 跳过锁，只管这一次：名单外的人能进这一回，下次清人照样被送走，离开后再进照样被拦。要整场都能进出就加进你自己锁的放行名单。权限由调用方自己查。管理员也有对应的强制送人命令。没更新的代理不认这个标记，SendResult.message() 会点名是哪几台。后台或 OP 用代理上的切服、送人命令进锁着的子服时也是这样：不看名单直接放进去，同样只管这一次，exemptMayEnter=false 也挡不住。

EvacuateReceipt.complete() 为 false 时看 proxiesAnswered / proxiesExpected：有代理没回，那台上的人可能没清；或者看 players() 里 FAILED 的人。

活动期间的奖励与游戏行为

子服锁着期间，内测 / 公测游戏的测试局不发积分（配置过的货币、经验照发）。这一条只看有没有锁，和下面的 eventRound 无关。

eventRound = true（默认）时，被锁子服上的游戏按活动目标子服对待，和内置活动一样：

  • HappyApi.eventModeHere() 为 true，小游戏据此暂停自动开局；
  • 游戏自己凑够人不会自动开局，OP 在管理面板「强制开始」或敲开局命令照常；
  • 只有放行名单和豁免的人能上场；
  • 自定义房照常发奖。

想让游戏照常自动开局时用 new LockOptions(false, lobby, msg, false)。
