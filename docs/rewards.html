奖励、等级与结算

7.6 发奖励：货币 / 等级 / 积分

奖励公式按规范第十一章计算，发放使用 RewardService：

RewardService rs = api.rewards();

// 结算：按 11.1 / 11.3 算完直接发
int[] coins = RewardFormula.payout(n, a, descriptor.sigma());
int exp = RewardFormula.exp(base, ratePerMin, minutes, cap, won, mvp);

rs.grant(playerId, RewardBundle.of(coins[rank - 1], exp), "spleef:win")
  .thenAccept(r -> {
      // 展示使用 r.granted()；访问 Bukkit 对象时切回主线程。
      if (r.leveledUp()) { /* 结算界面上标一下升级 */ }
  });

测试局奖励与活动局

测试阶段（内测 / 公测）的小游戏每打完一局会由框架发测试局额外奖励，默认为 1 点积分。 如果本服是当前活动的目标子服，活动局不会发这份积分，也不会提示未发放。 局中曾处于活动模式的，即使场控先结束活动、游戏后结算，也不会补发积分；其他子服的普通测试局照常发放。 测试局额外奖励中另行配置的货币和经验照常发放，提示只显示实际到账的项目。

不要自己接经济插件

三样东西每个服的叫法和后端都不一样：

是什么
CURRENCY 本服货币
EXP 等级经验
POINTS 积分

资产名称来自奖励配置。通过 rewards() 发放可复用当前经济后端与积分数据，并自动写入后台审计。

代码里不要写死货币名

Component name = rs.nameOf(RewardKind.CURRENCY);   // 本服货币的名字
Component line = rs.format(RewardKind.CURRENCY, 1250);  // 「1,250 + 货币名」（带本服配色）
Component lv   = rs.levelName();                   // 本服等级体系的名字

部分成功与实际回执

本服货币与积分分别提交。某个后端不可用或事务失败时，其他资产仍可能成功。 以 GrantResult.granted() 的实际数量和 skipped() 的失败项为准，不要按请求值显示到账或重复补发整包奖励。

rs.supports(kind) 用于检查后端配置；本次是否成功仍需检查回执。

经济插件晚于 FakeHappy 注册也没关系： ServiceRegisterEvent 会补接一次，日志里会打「货币后端已就绪」。 不用调整插件加载顺序。

扣钱走单独的接口

rs.takeCurrency(playerId, 500, "spleef:entry-fee").thenAccept(ok -> { ... });

RewardBundle 拒绝负数。扣款单独使用 takeCurrency 或经济 API，并检查回执。

经内置经济的扣款与流水在同一事务提交，后台统一查询资产流水。 需要按来源、操作者和对局检索时，使用 AuditContext 重载。 第三方经济后端的交易和本库审计不属于同一事务。

读值是非阻塞的

double money = rs.balance(id);          // 经济插件自己的内存缓存
LevelInfo lv = rs.level(id);            // 档案在玩家进服时异步载入
lv.level(); lv.progress(); lv.expToNext();

档案未载入时返回 LevelInfo.UNKNOWN，不会阻塞查询。显示等级和进度前先检查 lv.known()；未知状态的 maxLevel 为 0、isMax() 为 false。

离线玩家：

rs.levelAsync(id).thenAccept(lv -> ...);    // 等级
rs.pointsAsync(id).thenAccept(pt -> ...);   // 积分（pt.totalExp() 是积分总数）

两个都在查不到时返回 LevelInfo.UNKNOWN，同样用 known() 区分 「读不到」和「他真的是 0」。

两个子服同时给同一个人发奖励

不需要你做任何事，但值得知道底下发生了什么，因为这是最常见的形状： OP 在大厅用补发面板给一个正在小游戏服的玩家发奖励时，大厅这边看他「不在线」， 走的是数据库原子累加；小游戏服那边内存里还缓存着他的档案。

所以刷盘用的是 exp = exp + 增量 的增量合并，不是整行覆盖； 合并完再按库里的真值把等级列算一遍，并把结果写回本机内存那份档案。 只有 OP 面板的「覆盖」模式（setExp / setPoints）才整行写 —— 那时候本来就是「不管库里现在多少，就是要设成 N」。

玩家侧的两条命令

/level（别名 /lv）查自己的货币、两条曲线的等级与进度； 带一个玩家名是查别人，需要管理权限。离线玩家也查得到。 /level top [points] 是排行榜（60 秒缓存）。

/rewards（别名 /reward /jiangli）打开领取界面：两条曲线的档位铺在同一张表里， 三态格子（可领 / 已领 / 未解锁），红点数字来自「待领奖励」占位符。 无 GUI 的场景用 /rewards claim <key> 和 /rewards claimall。

开着自动领取（默认）时界面照样有用 —— 它是玩家看「我拿过什么」的地方。
