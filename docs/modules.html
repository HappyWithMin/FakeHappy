9. 写成模块（可选）

你的功能如果希望出现在模块管理列表里、能被 OP 在游戏内单独开关、 跟着 FakeHappy 一起热重载，就实现 HappyModule 注册进来。

通过 ModuleContext 注册的资源在模块关闭时统一回收。

public final class MyModule implements HappyModule {
    @Override public String id() { return "my-game"; }

    @Override
    public void onEnable(ModuleContext ctx) {
        ctx.listen(new MyListener());                 // 自动注销
        ctx.syncTimer(this::tick, 20L, 20L);          // 自动取消
        ctx.command("mygame", new MyCommand());       // 自动解绑
        ctx.onCleanup(() -> pool.close());            // 自定义清理，逆序执行
    }
}

不要在 onEnable 里直接调 Bukkit.getPluginManager().registerEvents 或 Bukkit.getScheduler() —— 框架收不回来。

配置约定：

  • 模块是否加载由框架的开关管理。
  • 每个模块有自己的一份配置（内建和外接都一样），里面就是本模块的键，不套模块名；ctx.config() 读的就是它。
  • 旧版配置开机自动迁移，迁移前备份。
  • 功能自己的开关沿用自己的配置键，与框架是否加载模块的开关分开。

服主可以查看模块实际的配置来源。用 ctx.config() 读取，不要把内部物理路径写死在拓展里；热重载后重新取配置。迁移遇到坏 YAML 或非法目标会停止，原配置与备份用于排查；不要据旧路径仍存在就认定它拥有最高优先级。

模块加载开关与功能内部开关分别管理，避免关闭某项行为时一并卸载依赖服务。
